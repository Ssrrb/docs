## Spec decisions

### a — Subtitle in Cargando and Error: hide it

Decision: hide the count line in both frames.

Exact instruction for the builder: in `CV-01 · Proyectos · Cargando` and `CV-01 · Proyectos · Error`, delete the PageHeader subtitle text shape that holds the literal `{n} en curso · {m} terminados`. Keep the title `Proyectos` and the header action. Substitute nothing; the spec defines no loading/error subtitle. The PageHeader count line is optional per `components.md` ("title, optional count line, actions"), so absence is contract-compliant.

Why:
1. better-writing: never ship a template artifact. A literal `{n}` on screen is a broken string; a templated string renders substituted or not at all.
2. The counts derive from the company index file (L2-43). In Cargando the file is not yet read; in Error it is unreadable. The line asserts data the application does not have.
3. The copy table defines `subtitle` for the populated screen only. An undefined state header stays silent rather than displays an unresolved template.

### b — Toolbar label `Buscar`: remove it

Decision: remove the label. Do not record it as Toolbar chrome.

Exact instruction for the builder: in the Toolbar instance of all seven frames, delete the text shape holding `Buscar` that precedes the search input. Keep the input with placeholder `Buscar proyectos` (key `search.placeholder`) and its search icon. At implementation, the input's accessible name is `Buscar proyectos` (`aria-label`); the placeholder alone must not be the accessible name.

Why:
1. README floor: Spanish copy comes from the spec exactly as written. `Buscar` is not a copy-table key; recording it in `components.md` would amend the copy set from the builder side, which is an author decision.
2. better-writing: the placeholder already carries the verb; a second `Buscar` does no work, and a bare verb string in a toolbar reads as a button label.
3. Workbench convention: toolbar search/filter inputs carry a placeholder only (components.md: Toolbar = "search, filters, view actions"). The visible-label floor scopes to forms (FormField), not toolbar filters.
4. If a visible label is later judged mandatory, the change is a spec amendment that adds a `search.label` key. Escalate to the spec author then; do not re-add chrome text.

# Calculation engine integration

*Decisions · none*

## Purpose

The budget arithmetic of Obra Studio comes from an external engine. This document holds the reason for that decision. This document holds the options that the team rejected. This document creates no rule.

## The decision

Obra Studio embeds the published package of the engine inside a webview of the fork of VS Code. The application does not fork the engine. The application does not run the engine as a separate process. The application does not reimplement the engine.

The engine is [open-calc-studio](https://github.com/OpenAEC-Foundation/open-calc-studio), read at commit `b470427`, which reports version `0.13.0`. The package is `@openaec/open-calc-studio`.

The engine provides the calculation only. The kinds of budget line are the kinds of Obra Studio. The document `docs/domain/budgets.mdx` holds those kinds.

## Why

| Option | Cost | Outcome |
|---|---|---|
| Embed the package | 8 to 12 person-weeks | Chosen |
| Fork the source of the engine | 12 to 18 person-weeks, plus 2 to 4 per quarter | Rejected |
| Run the engine as a separate process | 10 to 14 person-weeks, plus a second binary to sign | Rejected |
| Reimplement the calculator | 20 to 32 person-weeks | Rejected for the MVP |

The engine already publishes a package for a host page. That package rewrites its styles under the class `ocs-embed`, moves its dialogs into that class, and gates its keyboard shortcuts. Those three problems are the ones that break an embedded application. The engine solves them.

The workbench of VS Code does not use React. The engine uses React. The engine must run in a webview.

The Rust part of the engine writes the PDF report. The application does not use that part. The engine has a print service in TypeScript. The application prints that HTML with the `printToPDF` call of Electron.

## The relation between the kinds

The kinds of Obra Studio map to the record kinds of the engine. This mapping is unverified. A spike must verify it before the code starts.

| Kind of Obra Studio | Record kind of the engine |
|---|---|
| `rubro` | `chapter` |
| `subrubro` | `begrotingspost` |
| `línea` | `regel` |
| Surcharge line | `staart_*` |

The Dutch words must not appear in the interface of Obra Studio. The glossary of the interface must show `rubro`, `subrubro`, and `línea`.

## The relation between a budget line and a work unit

The engine holds one record type per budget line. Every record holds a stable `id`. That `id` survives a save and an open of a budget file. It does not survive a copy and paste inside the grid.

The field `resourceLibraryId` holds the reference to the work unit. No other part of the engine reads that field. No report prints it. No exporter writes it.

The following fields must not hold the reference.

| Field | Why the field is refused |
|---|---|
| `notes` | The user edits it. The exporters for BC3 and ONLV read it. |
| `ifcGuid` | The field accepts 22 characters. The engine does not renew it after a paste. |
| `code` | The field feeds the printed number of the line. |
| `verrekenbaar` | The field is a column of the printed report. |
| `branchId` | The field filters the grid. |

A second file must hold the relation from the work unit to the record. The file sits next to the budget file. The relation uses the `id` of the record.

A pasted budget line must name no work unit. The relation appears when the user assigns a work unit to the pasted line.

## Blockers

**No license text.** The repository of the engine holds no `LICENSE` file. The badge in its readme points to a missing file. Its `Cargo.toml` holds an empty `license` field. The application must not ship until the team holds the MIT text and the name of the copyright holder. The blocker applies to every option above.

**One vulnerable dependency.** The package `xlsx` at the version `0.18.5` holds two published vulnerabilities. The application must take the file from the vendor of the package instead of the public registry.

**One copyleft dependency.** The package `7z-wasm` holds the LGPL-2.1 license with the unrar restriction. The engine uses that package in one importer only. The application must drop that importer.

## Open questions

- The spike must measure the size of the bundle and must prove that the webview loads WebAssembly.
- The PDF path must show that `printToPDF` gives an acceptable report.
- The chain of surcharges of the engine applies 21% tax and 9% profit when a budget holds no chain. The document `docs/domain/budgets.mdx` holds that rule as pending.
- The engine ignores the currency of the project in the printed report. It always prints euros.
- The library of prices of the engine holds Dutch prices. The application needs Paraguayan prices.

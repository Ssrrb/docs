# Plan de ejecución de create-ctrl

*Execution · draft*

Este plan divide el sprint `create-ctrl` en objetivos verificables.
El contrato está en `docs/execution/create-ctrl-sprint.mdx`.
La evidencia de cada ronda está en `docs/execution/create-ctrl-evidence.mdx`.

## Reglas del plan

- Cada objetivo tiene una definición de terminado.
- Cada definición nombra la evidencia que la demuestra.
- La evidencia identifica el commit, la versión o el hash verificado.
- Un objetivo pasa a ✅ solo con toda su evidencia.
- Una prueba simulada no reemplaza una evidencia real.
- Un fallo de facturación de CI no equivale a una prueba aprobada.
- Si los bytes de un artefacto cambian, su evidencia vuelve a ⏳.

Estados: ✅ terminado, 🟡 parcial, ⏳ pendiente, ⛔ bloqueado.

## O7. Release estable `@ctrlmas/ctrl`

El procedimiento está en `docs/execution/ctrl-npm-release.mdx`.

Terminado cuando:

- O3, O4, O5 y O6 están en ✅.
- `freeze-release.mjs` acepta `platform-evidence.json` sin destinos incompletos.
- Los paquetes de `@ctrlmas` están publicados desde los tarballs congelados.
- Una instalación desde el registry funciona en cada destino.

Bloqueos:

- El 2026-10-17, el registry responde 404 para `@ctrlmas/ctrl`.
- La sesión npm y el permiso de publicación en `@ctrlmas` no están verificados.
- El contrato fija tres destinos iniciales; `ctrl-npm-release.mdx` lista seis paquetes nativos. El autor decide si el release estable exige los seis.

5. O6: subir y verificar el archivo de escritorio de cada destino.
6. O7: verificar el scope `@ctrlmas`, congelar y publicar.

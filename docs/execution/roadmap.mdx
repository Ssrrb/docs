# Roadmap

*Execution · draft*

## Purpose

This roadmap groups planned work into themes and initiatives. It gives an overview of work across the project.

The scope of the first delivery sits in `docs/product/mvp.mdx`. This roadmap holds the work that that document leaves out. This roadmap holds the work that a document of the domain states as pending.

## Status

| Status | Meaning |
|---|---|
| Candidate | The work needs more definition. |
| Exploring | The team is learning about the problem and possible solutions. |
| Blocked | The work cannot start until another party acts. |
| Planned | The team has selected the work, but has not started it. |
| In progress | The team is working on the initiative. |
| Done | The team has completed the initiative. |
| Deferred | The team has moved the initiative out of the current focus. |

## Blockers

The MVP cannot ship until these two items close. Neither is code.

| Blocker | Why | Status |
|---|---|---|
| The license text of the engine | Neither the engine nor its report library holds a `LICENSE` file. MIT requires the notice and the name of the copyright holder. | Blocked |
| The spike of the webview | Nobody has proved that the engine package loads inside a VS Code webview with WebAssembly enabled. | Planned |

The document `docs/decisions/motor-integration.mdx` holds the detail of both items.

## Themes

### Engine

The engine is external code. The team consumes it and does not change it. The work below keeps the application safe against the engine and correct in Paraguay.

#### License of the engine

- Outcome: The team holds the MIT text and the name of the copyright holder.
- Status: Blocked
- GitHub issue: none yet

#### Spike of the embedded engine

- Outcome: A branch of the fork loads the budget grid in a webview, with WebAssembly, at an acceptable load time.
- Status: Planned
- GitHub issue: none yet

#### Vulnerable and copyleft dependencies

- Outcome: The bundle takes `xlsx` from its vendor, and the importer that needs `7z-wasm` is gone.
- Status: Planned
- GitHub issue: none yet

#### Printed report in dollars

- Outcome: A printed budget shows the currency of the project. The engine prints euros today.
- Status: Planned
- GitHub issue: none yet

### Domain debt

The engine holds a Dutch domain. The application needs a Paraguayan one. The work below replaces the terms and the concepts.

#### Surcharge chain of Paraguay

- Outcome: The team writes the surcharges and the rates of the Paraguayan chain. The structure of the chain exists. The values do not.
- Status: Candidate
- GitHub issue: none yet
- Related work: `docs/domain/budgets.mdx` holds these rates as pending. `docs/product/mvp.mdx` holds the rule that stops the Dutch chain.

#### Glossary of terms

- Outcome: A table holds every Dutch term of the engine beside its Paraguayan term.
- Status: Candidate
- GitHub issue: none yet

#### Precision of an amount

- Outcome: A rule states the decimals and the rounding of every amount of the application.
- Status: Done
- Related work: `docs/domain/budgets.mdx` holds the rules L1-49 and L1-50.

#### Library of Paraguayan prices

- Outcome: The application offers Paraguayan prices for the common inputs. The library of the engine holds Dutch prices.
- Status: Candidate
- GitHub issue: none yet

### Unfinished domain rules

The documents of the domain name these rules as pending. The team must write them before the domain is approved.

#### States of a purchase request

- Outcome: A rule states the states of a purchase request.
- Status: Done
- Related work: `docs/domain/purchase-requests.mdx` holds the rule L1-66.

#### Cancellation of a purchase order

- Outcome: A rule states whether a purchase order can be cancelled after its approval, and what happens to the budget.
- Status: Candidate
- Related work: `docs/domain/purchase-orders.mdx`

#### The relation between a budget line and a work unit

- Outcome: A second file holds the relation. The engine writes the reference in the field `resourceLibraryId`. Nobody has proved that the relation survives a copy and paste.
- Status: Exploring
- Related work: `docs/domain/budgets.mdx`, `docs/decisions/motor-integration.mdx`

### Access

One user account holds every capability. The capabilities exist. The work below puts a second account in front of them.

#### A second role

- Outcome: One account issues a document and another approves it. The separation of duties applies to the purchase order and to the certificate.
- Status: Candidate
- Related work: `docs/system/permissions.mdx`, `docs/domain/certificates.mdx`

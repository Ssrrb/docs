# Collection

*Domain · draft*

## Purpose

The name `cobro` names this entity. A collection records the money that a client pays a project for the work that an approved advance certificate certifies. The ERP owns the collection.

A collection cancels all or part of the amount of one approved advance certificate. A collection records the client, the method, the reference, the date, and the evidence of the transfer.

A registered collection never changes. A mistake is corrected by cancelling the collection with a reason and registering another one.

## Rules

### Creation of a collection

Only the ERP must register a collection.

### Client of a collection

A collection must name exactly one client of the list of its project.

### Certificate of a collection

A collection must name exactly one advance certificate.

### The named certificate must be approved

A collection must name an advance certificate that is in the state `aprobado`.

### Project of a collection

A collection must belong to the same project as its advance certificate.

### Amount of a collection

A collection must declare exactly one amount. The amount of a collection must be greater than zero.

### Method of a collection

A collection must declare exactly one method. The methods are `transferencia`, `cheque`, and `efectivo`.

### Reference of a collection

A collection must declare exactly one reference.

### Date of a collection

A collection must declare exactly one date.

### Evidence of a collection

A collection must hold zero evidence files or more.

### State of a collection

A collection must declare exactly one state.

### A registered collection never changes

A collection in the state `registrado` must not change.

### No deletion of a registered collection

The application must not delete a collection in the state `registrado`.

### Reason of a cancellation

The cancellation of a collection must record one reason.

### Hard ceiling on a collection

The application must not register a collection that would make the collected amount of an advance certificate greater than the amount of that certificate.

### Partial collection

A collection must cancel all or part of the amount of its advance certificate.

### A cancelled collection does not count

A cancelled collection must not contribute to the collected amount of an advance certificate.

### Collected amount of an advance certificate

The collected amount of an advance certificate must equal the sum of the registered collections that name that certificate.

## Example

The states of a collection follow this order.

| State | Meaning |
|---|---|
| Draft | The user edits the collection. |
| Registered | The money entered the project. The collection counts. |
| Cancelled | The collection was wrong. It keeps its record and stops counting. |

## Example

A certificate of 8,000,000.00 accepts collections until the collected amount reaches that amount.

| Collection | Amount | Collected amount of the certificate | Available to collect |
|---|---|---|---|
| First | 5,000,000.00 | 5,000,000.00 | 3,000,000.00 |
| Second | 3,000,000.00 | 8,000,000.00 | 0.00 |
| Third | 1.00 | 8,000,000.00 | 0.00 |

The application refuses the third collection.

## Notes

A collection records the money that enters a project. A payment records the money that leaves a project. The document `docs/domain/payments.mdx` holds the payment.

The cashflow report shows the registered collections and the registered payments of every currency. The document `docs/product/mvp.mdx` holds the report. The document `docs/domain/companies.mdx` holds the sums of the two.

# Proveedor

*Domain · draft*

## Purpose

A `proveedor` (supplier) is a company that the project buys from or signs a subcontract with. A project holds a list of `proveedor`. A `proveedor` holds no category.

The name `proveedor` names the record. The record has no kind. The document that names a `proveedor` gives its role. A `proveedor` acts as a supplier when a purchase order names it. A `proveedor` acts as a subcontractor when a subcontract contract names it.

The same record carries both roles. A company that sells cement and that builds foundations is one `proveedor` in the list of the project.

## Rules

### L1-60 — Name of a proveedor

A `proveedor` must declare one name.

### L1-61 — List of proveedores

A project must hold exactly one list of `proveedor`.

### L1-62 — No category

A `proveedor` must not declare a category. A `proveedor` must not declare a kind.

### L1-63 — Role in a purchase order

A purchase order of a project must name exactly one `proveedor` of the list of that project.

### L1-64 — Role in a subcontract contract

A subcontract contract of a project must name exactly one `proveedor` of the list of that project.

### L1-65 — No price at a proveedor

A `proveedor` must not declare the price of an input. The price list of a project holds the price of an input.

## Example

One record carries both roles.

| Proveedor | Named by a purchase order | Named by a subcontract contract |
|---|---|---|
| Hormigón del Sur | Yes | Yes |
| acero Paraguayo | Yes | No |
| Fundación SRL | No | Yes |
